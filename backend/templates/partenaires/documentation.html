Documentation — API Partenaires

Intégrez le catalogue de restaurants EEUEZ et la création de commandes dans votre propre plateforme. Accès soumis à vérification (KYB) — candidatez ici si vous n'avez pas encore d'identifiant.

V1 : commandes en mode especes uniquement (le partenaire encaisse déjà son client final, ou paiement à la livraison/au retrait). Pas de collecte Mobile Money CamerPay pour le compte d'un tiers pour l'instant.

Authentification — clé + signature HMAC

Chaque requête est authentifiée par une clé API et signée en HMAC-SHA256 (pas d'OAuth2, pas de session) — trois en-têtes obligatoires :

En-têteContenu
X-EEUEZ-KeyVotre api_key (identifiant, pas secret)
X-EEUEZ-TimestampHorodatage Unix (secondes) — tolérance de 5 minutes
X-EEUEZ-SignatureVoir recette ci-dessous

Message à signer : timestamp|METHODE|chemin_complet|sha256(corps) — chemin_complet inclut la query string (ex. /api/partners/v1/plats?restaurant=12) ; sha256(corps) est le SHA-256 hexadécimal du corps brut (chaîne vide pour un GET).

Exemple Python

import hashlib, hmac, time, requests

api_key = "pk_sandbox_..."
secret = "..."                     # reçu une seule fois à l'émission
method, path = "GET", "/api/partners/v1/restaurants"
timestamp = int(time.time())
body_hash = hashlib.sha256(b"").hexdigest()

message = f"{timestamp}|{method}|{path}|{body_hash}"
signature = hmac.new(secret.encode(), message.encode(), hashlib.sha256).hexdigest()

r = requests.get("https://menu.cambus.cm" + path, headers={
    "X-EEUEZ-Key": api_key,
    "X-EEUEZ-Timestamp": str(timestamp),
    "X-EEUEZ-Signature": signature,
})

Exemple cURL (POST avec corps)

# body.json = corps EXACT envoyé (la signature porte sur son sha256)
TS=$(date +%s)
BODY=$(cat body.json)
HASH=$(printf '%s' "$BODY" | sha256sum | cut -d' ' -f1)
MSG="$TS|POST|/api/partners/v1/commandes|$HASH"
SIG=$(printf '%s' "$MSG" | openssl dgst -sha256 -hmac "$SECRET" | cut -d' ' -f2)

curl -X POST https://menu.cambus.cm/api/partners/v1/commandes \
  -H "X-EEUEZ-Key: $API_KEY" -H "X-EEUEZ-Timestamp: $TS" -H "X-EEUEZ-Signature: $SIG" \
  -H "Content-Type: application/json" -d "$BODY"

Créer une commande

POST /api/partners/v1/commandes
{
  "restaurant": 12,
  "reference_externe": "ORD-2026-000123",
  "items": [{"plat_id": 45, "quantite": 2}],
  "emporter": true,
  "mode_paiement": "especes",
  "notes": "Sans piment"
}

reference_externe est obligatoire : c'est votre identifiant, réutilisé comme clé d'idempotence — renvoyer la même valeur après un timeout réseau renvoie la commande déjà créée (200) au lieu d'en créer une deuxième.

Réponse : id, statut, montant_total, code_retrait (retrait sur place), lignes. Les montants internes (commission, part restaurant) ne sont jamais exposés.

Codes d'erreur

CodeSignification
400Payload invalide, ou motif métier stable (ex. ferme, hors_zone, aucun_plat_valide)
401Clé/signature invalide, horodatage expiré, ou partenaire suspendu
403Action hors de la portée de votre plan (ex. écriture de commandes sur le plan Découverte)
404Ressource introuvable (ou appartenant à un autre partenaire)
429Débit court terme dépassé, ou quota mensuel du plan atteint

Webhooks

Si configuré (plan Business+), chaque changement de statut d'une de vos commandes déclenche un POST signé vers votre URL :

{
  "commande_id": 981,
  "reference_externe": "ORD-2026-000123",
  "statut": "acceptee",
  "montant_total": 6500,
  "timestamp": 1780000000
}

En-tête X-EEUEZ-Signature = HMAC-SHA256 du secret webhook (distinct de votre secret API) sur commande_id|reference_externe|statut|timestamp — même recette que ci-dessus, à vérifier avant de faire confiance au corps reçu.

Sandbox vs Live

Chaque identifiant est émis pour un environnement : sandbox (test, aucun impact réel) ou live (commandes réelles, réservé aux plans qui l'incluent). Les préfixes de clé (pk_sandbox_… / pk_live_…) permettent de les distinguer d'un coup d'œil dans vos logs.
